# Demo script (about 3 minutes)

The story: **the runbooks tell you what to do in general. Memory knows what happened here.**
The demo uses one honest comparison and one live lesson. Do not claim more than the data shows.

## Before you record (checklist)

1. Use a **fresh bank** that has never received the lesson. Set `HINDSIGHT_BANK_ID` in `.env` to a new name
   (for example `incident-response-demo-1`), restart the backend, run `python scripts/seed_memory.py`, then wait
   one minute.
2. Delete `data/runtime` so runbook statistics start from the seed data:
   `Remove-Item data\runtime -Recurse -Force -ErrorAction SilentlyContinue`.
3. Confirm the fresh bank does not already know the lesson: analyze the alert in step 3 below and check the answer
   does **not** mention `fx_live_rates`.
4. Confirm `LLM_API_KEY` is set so the no-memory column works.
5. Record one complete clean take first. Keep it as the backup. To record again, use another new bank name.
6. Do not narrate the word "AI" more than necessary. Show the screen.

## 0:00 to 0:20: the problem

Say: "It is 3 a.m. An alert fires. The answer is in old tickets and in the heads of engineers who are asleep, so
teams repeat fixes that already failed."

## 0:20 to 1:10: what memory adds to an ordinary alert (Compare mode)

1. Choose the demo alert **Latency + 502s after a deploy**. Choose **Compare** and click the button.
2. Point out honestly: "Without memory, the model reads the alert and the runbooks and also says roll back.
   The alert says a deploy just happened, so that is fair."
3. Then show what only memory can show, on the right:
   - **Avoid, it already failed here**: restart and scale-out, with the incident IDs where they failed.
   - **Runbook track record**: scale-out (RB-07) *worked 0 of 3*, counted from recorded outcomes.
   - **Evidence**: open one card and show what Hindsight remembered.
4. Say: "The first step is the same. The difference is proof and history."

## 1:10 to 2:25: it learns something no runbook contains (the main moment)

1. Enter this alert (or use the saved values), choose **Compare**, analyze:
   - Alert: `Payment authorizations timing out, p95 latency 4.1s`
   - Log: `WARN fx_client: timeout after 2000ms calling rates-service /v2/quote`
   - Context: `No deploys in the last 7 days.`
2. Say: "Neither has seen this before. Without memory it suggests scaling out. Memory has no precedent."
3. In **Did it work?** record the fix:
   - Add **Scale out the service**, mark it *Did not work*.
   - Add **Other step**: `Disable feature flag fx_live_rates so authorizations use cached FX rates`, mark it *Worked*.
   - Root cause: `the third-party rates-service was timing out and live FX lookups sat on the authorization path`
   - Cause tag `upstream_fx_timeout`, minutes `18`, incident ID `INC-011`. Click **Save to memory**.
4. Change the alert to the follow-up and analyze in **Compare** mode:
   - Alert: `Authorization latency spike, p95 3.7s`
   - Log: `WARN fx_client: timeout after 2000ms calling rates-service /v2/quote (retry 2/3)`
   - Context: `No recent deploys.`
5. Say: "Now memory recommends disabling the feature flag and cites the incident the engineer just recorded.
   Without memory, it still says scale out. That fix lives in no runbook. The team taught it in one minute."

In our rehearsal the lesson was used about 8 seconds after it was saved. Leave a short pause anyway and keep the
recorded take as the backup.

## 2:25 to 2:50: how Hindsight is used

Show the architecture slide. Say: "Retain stores incidents and outcomes with time and tags. Recall finds the
evidence. Reflect reasons over it and returns a structured recommendation. The counts on screen are computed from
recorded outcomes, not generated by the model."

## 2:50 to 3:00: close, with the limits

Say: "The data is synthetic, and a human makes the final call. The agent gets better with every incident the team
records."

## Likely questions and honest answers

- **Is this just search over runbooks?** On alerts that map to a runbook, a good model with the runbooks does about
  as well: 5 of 6 first actions were right without memory in our small test. Memory earns its place on lessons that
  are in no runbook, on cited evidence, and on track records.
- **Where does the data come from?** It is synthetic, modeled on patterns in public postmortems. The repository says so.
- **Why does it take about ten seconds?** Reflect is an agentic reasoning step over memory. Recall alone is much faster.
- **What if an old lesson becomes wrong?** Not handled yet. There is no supersession model, and that is listed as a limit.
- **How would this scale to many teams?** One bank per tenant. Tags are a soft partition inside one bank.
- **Can it act on its own?** No. It is decision support and never executes a step.
